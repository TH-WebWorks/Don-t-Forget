\# Iteration Rules – Don’t Forget



This file defines how we iterate on the app.



The goal is to move quickly without drifting from the core vision.



---



\## Current focus



We are currently designing and refining:



1\. Daily Orientation screen

2\. Adjust flow (minimal)

3\. Daily check-in question

4\. Skip / empty-day behavior



Nothing else is in scope.



---



\## Iteration rules



\- Change one thing at a time

\- Prefer removing UI over adding UI

\- Prefer fewer words over more words

\- Prefer defaults over configuration

\- Prefer reading over editing



---



\## How to evaluate a change



Every change should answer at least one:

\- Does this reduce cognitive load?

\- Does this make the app calmer?

\- Does this make the next step clearer?



If it adds:

\- tracking

\- lists

\- dashboards

\- metrics

\- setup steps



It is likely wrong.



---



\## Cursor usage rules



When using Cursor:

\- Ask for small, localized changes

\- Never ask for “features”

\- Never ask for “improvements” without context

\- Always specify the file being changed

\- Always reference Guidelines.md when in doubt



Good prompt:

> “Adjust this component to reduce visual weight, following Guidelines.md.”



Bad prompt:

> “Make this more useful.”



---



\## Definition of progress



Progress is:

\- better clarity

\- less UI

\- fewer decisions

\- shorter sessions



Progress is not:

\- more screens

\- more logic

\- more options
